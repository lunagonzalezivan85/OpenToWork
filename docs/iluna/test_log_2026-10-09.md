## Correcciones aplicadas en esta fase

1. **H-39 (Crítica)** — `candidates/search` + `search/skills` exigen empresa `IsVerified=true` (403 si no). Antes bastaba cualquier login.
2. **H-40 (parcial)** — mecanismo de verificación: `PUT /api/admin/companycrm/companies/{id}/verified` (audit log incluido). La empresa nueva ya no opera sin verificar el correo (código obligatorio).
3. **H-41** — `send-code` responde igual si el correo existe (aviso por correo al titular, plantilla `RegistrationAttemptNotice`); el registro consume el código **antes** de chequear duplicado, así que la existencia del correo no es deducible.
4. **H-31** — logout real: página `/logout` + menú revocan el refresh token (`RevokeTokenAsync` ahora envía el Bearer) y limpian todo el storage.
5. **H-29/H-30** — guard global `CascadingAuthenticationState` + `AuthorizeRouteView` + `RedirectToLogin`; 22 páginas con `[Authorize]`/`Roles=`; claims `role` en array expandidos a claims individuales; token expirado = anónimo.
6. **H-43 (parcial)** — `next`/`returnUrl` rechazan `//` y `/\` (open redirect).
7. **H-05** — `appsettings.json` del WASM sin `localhost`; la URL dev se movió a `appsettings.Development.json`.
